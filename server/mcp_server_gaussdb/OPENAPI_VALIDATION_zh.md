# GaussDB MCP 0.3.2 OpenAPI 接入与验证报告

## 接入范围

服务从官方 SDK 动态发现 265 个请求型 OpenAPI，并通过 5 个目录工具统一提供：

- `list_openapi_operations`
- `describe_openapi_operation`
- `invoke_read_openapi`
- `invoke_write_openapi`
- `invoke_dangerous_openapi`

目录包含 149 个 READ、66 个 WRITE、50 个 DANGEROUS 操作，覆盖实例生命周期、备份恢复、数据库与用户、SQL 诊断、参数、网络安全、标签、配额计费、任务事件、回收站、监控、插件和容灾等分类。加上 17 个高频场景工具，MCP 对外注册 22 个工具。采用目录调用是为了避免把 265 份接口结构同时放入模型上下文。

`describe_openapi_operation` 会返回字段类型、Wire 名称、嵌套模型、字段说明和必填项。接口必须走与目录分类一致的风险通道；DANGEROUS 调用必须传入 `confirm=true`。当请求带 `instance_id` 时，危险操作会重新读取云端实例并检查保护 ID、名称和标签。

创建选型已追加北京四纯查询验证：引擎版本 `10.0.0` 实时返回 `single`（单副本）、`triset`（1 主 2 备）和 `logger`（1 主 1 备 1 日志）三种集中式模板；基础版分布式通过 `combined` 规格族查询，企业版分布式通过 `enterprise` 规格族查询。磁盘类型和可用区同样来自实时接口。本次看到的规格数量只记录验证当时的区域状态，MCP 不固化数量或规格码。本次验证没有创建或变更实例，机器可读摘要见 `create-options-validation.json`。

参数修改增加了强制实时预检：未知、只读和缺失 `readonly=false` 证明的参数均会阻断；类型与明确值域先本地校验；无变化请求不写入；需要重启或命中敏感参数分类的修改必须二次传入 `confirm=true`。北京四参数模板只读查询确认云端返回 `readonly`、值域、类型、说明和重启元数据；本轮没有活动测试实例，因此未执行参数写入。
